# Teaching Loop

Use for an explanation, guided lesson, correction, or one-off practice.

## Locate the confusion

Identify whether the request concerns a concept, procedure, notation, or interpretation. When the message already makes the next move clear, teach or answer directly. Ask one clarifying question only when the ambiguity would materially change the explanation or exercise. Use the learner's phrasing and shown work to choose a starting level, then adjust from their response.

## Select the smallest useful mode

- **Teach:** a model is missing or wrong. When the learner has any foothold, ask for a guess, prediction, or rough solution before explaining; then teach by contrasting their attempt with the canonical model and naming the exact divergence. Give the correct model right after the guess. Open with a worked example only when the material has many interacting parts and they have no foothold.
- **Guided practice:** the model is plausible but execution depends on support. Have the learner explain why each worked step is valid and what breaks if it is skipped; do not let them read the example passively. Remove support as evidence improves. For teach-back, say in advance that the explanation will be questioned.
- **Independent rep:** the model exists but recall, fluency, or transfer is weak. Ask for a fresh attempt before giving a solution.
- **Assessment:** capability is uncertain, a baseline or milestone is needed, or the learner is returning after a gap. Do not use it as the default opening when instruction is the limiting need.
- **Repair:** an attempt reveals a missing prerequisite or incorrect causal rule. Stop drilling; teach the smallest broken atom and retest it in a changed context.

State the capability target and selected mode at the start of a substantial lesson. Do not narrate this ritual for a simple answer.

Place difficulty deliberately, because the mode decides which way it cuts. While a model is still being acquired, difficulty competes for the working memory that understanding needs, so strip it out. Once the model exists, difficulty is the instrument: effortful retrieval is what converts it into storage strength.

## Explain a mental model

1. Name the concrete situation the model helps with.
2. State the governing rule: triggers, inputs, constraints, state changes, and observable outputs.
3. Build from the smallest necessary atoms; avoid unexplained jargon and anthropomorphic "magic."
4. Show one representative worked example or trace when it reduces ambiguity.
5. Ask for a prediction, explanation, decision, or small application proportionate to the goal.

Use literal explanation before analogy. Use an analogy only when its causal structure matches and it makes the next technical rule easier to understand.

Teach one strategy at a time and make it explicit rather than expecting it to be inferred from an example. Transfer to a new context is not automatic: if the capability needs to hold outside the setting it was taught in, practice it in a second setting rather than assuming generalisation.

## Scaffold without replacing thought

Use this order when the learner is stuck. It is deliberately progressive: each step is the smallest disclosure that could unblock the next decision, and the answer is the last resort, not the second one.

1. locate the exact step or assumption that broke;
2. reduce the problem to one atom or variable;
3. restate the goal from a different angle or give a partial example;
4. provide the smallest hint that unblocks the next decision;
5. give the direct answer when the learner requests it, the goal is explanation, or further struggle has stopped producing evidence; follow **Help or direct answer** in `SKILL.md`.

A hint narrows the space; it leaves the operation for the learner to name. "Have you tried multiplying both sides by x?" is the answer with extra steps. When the original problem is still the live rep, work a parallel problem with the reasoning narrated, then hand the method back for their own attempt.

For a multi-variable task, offer a compact external stack: active variables, invariants, and current goal. For initiation friction, offer an optional zero-entry action such as naming the inputs. External scaffolds (a visible checklist, a written goal, a stated invariant, a timer) carry load that would otherwise compete with the reasoning; use them freely, and keep them visible rather than implied.

## Use meaning and distinctiveness selectively

Anchor a model in a concrete goal, consequence, or situation when that makes its purpose clearer. Where the material allows it, draw the example from something the learner is already deeply interested in: a genuinely engaging concrete case sustains the focus that the reasoning needs, and a bridge from an existing interest costs less working memory than a neutral one.

Use a surprising, humorous, or emotionally meaningful example only when it clarifies the governing rule or consequence. Keep the cue tied to the target relationship. A memorable but irrelevant story can make the detail memorable while weakening understanding of how it fits. Follow it with retrieval or application; distinctiveness is an encoding aid, not evidence of learning.

## Correct with evidence

For a substantial rep, name the target or comparison standard first: success criteria, a rubric, a reference output, a trace, or an exemplar. State what the attempt correctly establishes. Then identify the rule or boundary that caused the gap, not a trait of the learner. Show the counterexample or causal trace, give one repair action, and ask for a changed attempt when practice is the goal.

A teaching interaction is complete when the requested question is answered or the selected capability has produced evidence. Do not force an artifact after a short informational exchange.

## Check what was actually built

Before closing a substantial teaching interaction, distinguish what the learner can now do from what merely made sense while it was in front of them. Smooth performance immediately after an explanation does not establish lasting retention; see the retrieval and storage strength distinction in `SKILL.md`.

The cheap test: ask them to state the governing rule and one boundary condition without scrolling back. If that is shaky, diagnose whether recall or the model itself is missing, then select retrieval or repair for the next contact.

## AI boundary

AI may clarify, generate counterexamples, simulate inputs, inspect reasoning, and pressure-test a completed attempt. It should not silently perform the first-pass reasoning that the learner is trying to build.

The operating rules (cold start, turn discipline, the learner grades first, nothing promotes from an assisted solve, frustration breaker) are in `SKILL.md` under **Assisted performance is not evidence**. They apply to every learning-critical interaction, not only to courses.
